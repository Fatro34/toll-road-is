# 7.5. Итоговое заключение по результатам тестирования

## 1. Сводные показатели испытаний
* **Функциональное тестирование (7.1):** выполнено **12 тест-кейсов** (`TC-01` – `TC-12`), охватывающих навигацию, фильтрацию, поиск по справочнику тарифов (`R1`), CRUD-операции, расчёт стоимости проезда и формирование отчётности. Успешно пройдено без замечаний — **10 сценариев (83,3 %)**, выявлены замечания по валидации ввода и ролевой модели — **2 сценария (16,7 %)**.
* **Нагрузочное тестирование (7.3):** на базе `toll.db` (9 нормализованных таблиц) сгенерировано **1 000 записей** проездов (итого **1 003 записи** в таблице `Trip`). Пакетная вставка выполнена за **11 мс**, агрегирующий запрос (`COUNT`, `SUM`, `AVG`) — за **15 мс**. Потребление ресурсов клиентом `POSINV.exe` составило **0,2 % ЦП** и **22,7 МБ ОЗУ**.

## 2. Рекомендации по доработке (план исправлений)
1. **Устранение `BUG-01`:** перевести слой доступа к данным (`SQLiteDataAccess.cs`) с унаследованной таблицы `PRODUCT` на целевую схему `Tariff` / `Trip` с явным приведением числовых полей (`CAST(Cost AS REAL)` / `double`).
2. **Устранение `BUG-02`:** добавить на форму добавления/редактирования тарифа проверку `Cost > 0` с выводом предупреждения `MessageBox` до выполнения SQL-запроса `INSERT`/`UPDATE`.
3. **Устранение `BUG-03`:** при инициализации формы проверять `CurrentUser.RoleId` и отключать (`Enabled = false`) вкладки редактирования магистралей и классов ТС для роли «Оператор».

## 3. Общий вывод
Базовая функциональность работы с реляционной базой данных `toll.db`, справочниками тарифов и расчётными операциями работоспособна и выдерживает проектную нагрузку с многократным запасом по времени отклика. Система рекомендована к опытной эксплуатации после устранения дефектов `BUG-01` – `BUG-03`.
